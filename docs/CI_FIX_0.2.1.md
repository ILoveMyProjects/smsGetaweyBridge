# HACS / Hassfest CI fixes — v0.2.1

This release addresses the exact findings reported for the GitHub Actions run [39038011472](https://github.com/ILoveMyProjects/smsGetaweyBridge/actions/runs/39038011472).

## Fixed in source code

- **Hassfest MANIFEST ordering:** `custom_components/smsgetaweybridge/manifest.json` now lists `domain`, `name`, and the remaining keys alphabetically.
- **Hassfest CONFIG_SCHEMA:** `custom_components/smsgetaweybridge/__init__.py` declares `CONFIG_SCHEMA = cv.config_entry_only_config_schema(DOMAIN)`, since configuration is done through a GUI config entry and not YAML.
- **HACS brand validation:** `custom_components/smsgetaweybridge/brand/icon.png` and `dark_icon.png` are bundled. This is the recommended custom integration brand location for HA 2026.3+.
- **Actions Node.js 20 warnings:** workflow-owned `actions/checkout` and `actions/setup-python` references target versions using Node.js 24.
- **Version:** `manifest.json`, changelog, release build checks and panel static asset cache version are now `0.2.1`.

## Required GitHub repository settings (cannot be fixed by pushing the source ZIP)

Go to <https://github.com/ILoveMyProjects/smsGetaweyBridge> and edit **About** (gear icon):

- **Description**: `Local Home Assistant SMS integration for SMS Gateway for Android`
- **Topics**: `home-assistant`, `hacs`, `sms`, `sms-gateway`, `android`
- Ensure the repository is **public** and **Issues** are enabled under **Settings → General → Features**, if the goal is inclusion in the HACS default catalog.

These are GitHub repository properties. Putting this information into `README.md`, `hacs.json`, or `manifest.json` does **not** populate them automatically.

## Publication order

1. Upload/commit the **contents** of the source archive to the root of the GitHub repository. Keep `.github/workflows/tests.yml` and `custom_components/` in their directories.
2. Update the GitHub repository **About** metadata described above.
3. Check the branch CI jobs (Python, HACS, Hassfest) have passed.
4. Push a **new** version tag `v0.2.1` for the commit on that branch (see `docs/RELEASING.md`). Do **not** move or reuse tag `v0.2.0`.
5. The release job should run only after all three jobs succeed; check GitHub Actions and Releases for the actual outcome.
